# Susnix top bar

A Quickshell panel on each monitor with 26px sides and a 36px center task
section, with a dark translucent surface,
centralized blue/violet theme, color cube button, centered current task, and status
widgets. The editable task includes a completion/archive button and a dropdown
for upcoming tasks and today's completed tasks. The bar and task retract after
the pointer leaves and reveal from the top edge. The task's lock button pins only
the task section; its setting survives restarts. A compact cube selector expands beneath the top-left color icon. The adjacent
sliders button opens the control center.

The stock Hyprland warning is controlled by `hl.config({ autogenerated = true })`
in `~/.config/hypr/hyprland.lua`. That flag has been removed from the repository
config. Remove that one line from an existing installed config and run
`hyprctl reload` to dismiss the banner without hiding actual configuration errors.

## Installation and launch

The existing bootstrap installs `quickshell` from `packages/desktop.txt` and
copies this configuration into `~/.config/quickshell/susnix`, matching its existing
Hyprland config installation model. It preserves target-user ownership.
`configs/hypr/hyprland.lua` starts one instance on `hyprland.start` using
the supervised helper with an explicit Wayland backend for this process.
Existing packages and key bindings are preserved.

For an existing desktop, copy the updated configuration once:

```bash
mkdir -p ~/.config/quickshell/susnix
cp -R configs/quickshell/. ~/.config/quickshell/susnix/
bash ~/.config/quickshell/susnix/bar.sh start
```

For a checkout instance, use this command to reload a running bar or start it
if stopped:

```bash
bash /home/levi/susnix/configs/quickshell/bar.sh reload
```

For the installed instance:

```bash
bash ~/.config/quickshell/susnix/bar.sh reload
```

`bar.sh` runs one bar in the shared transient systemd user service
`susnix-bar.service`. A runtime lock serializes checkout and installed launches;
starting either replaces the other. The helper stops legacy path-specific
services before removing their instances, preventing restart loops from stacking
bars. Recognized Susnix configuration paths are targeted; other shells are untouched. It survives closing the terminal and restarts on
unexpected exits after two seconds. Five starts within 30 seconds stop
recovery rather than creating an endless crash loop. `reload` checks IPC and
starts the bar when stopped. An existing unmanaged instance of the same config
is restarted into supervision. Other Quickshell configurations are untouched.
`restart` explicitly restarts the bar, `stop` stops recovery as well as the bar,
`status` shows service state, and `logs` shows its last 60 journal entries.
Startup succeeds only after the bar's IPC handler responds.

The helper uses Wayland and defaults to `QT_QUICK_BACKEND=software`, avoiding the
VM's previously observed accelerated-rendering crash. Set `QT_QUICK_BACKEND` to
your preferred backend before launching to override it. Session environment is
passed to this service only. Run the helper inside an active Hyprland terminal;
a TTY or remote editor terminal without `WAYLAND_DISPLAY` cannot launch a panel.

Hyprland autostart now calls the installed helper. Apply the updated startup
line to the installed Hyprland config for the next login; config reload does not
rerun the startup hook. Both installed and checkout launch helpers now use the same service, so they
cannot create two supervised bars. Direct raw Quickshell launches bypass the helper;
use `bar.sh restart` to clean up recognized old Susnix instances. Installation preserves the existing
copy model and includes the helper automatically.

The raw `quickshell ipc ... call bar reload` command requires a running instance
and cannot resurrect a stopped bar. Use the helper for routine launch/reload.
Quickshell still automatically reloads QML when files change.

## VM resizing and display sharpness

The panel remains anchored to the current monitor width. Resize changes apply
immediately; only the separate 6px task-focus expansion is animated. The desktop
monitor rule uses `preferred` mode and scale 1, rather than a forced HD resolution.
On smaller screens the status row drops secondary detail instead of shrinking
fonts. Task dropdown height is limited to the current screen's usable height.

`HiDpiCanvas.qml` provides a backing image at the window's current device pixel
ratio. Outline, glass, hover effects, and skyline regenerate at that density;
SVG icon raster sizes also follow display density. Native Qt text follows the
output scale. No enlarged screenshot or permanently fixed 1920×1080 surface is
used. Repeated grow/shrink tests covered 640–3840 logical pixels at 1×, 1.5×, and
2× device pixel ratios, with no overlap or off-center task and no runtime errors.

For VirtualBox, `bootstrap.sh --vm` enables the resize bridge alongside the
existing guest service. Existing installations can enable it once with:

```bash
bash /home/levi/susnix/scripts/setup-vm-display.sh
VBoxClient --vmsvga-session --session-type wayland
bash ~/.config/quickshell/susnix/bar.sh restart
```

The setup script requests sudo to install/enable the root resize bridge. It uses
a distribution-provided `vboxdrmclient.service` if available, otherwise installs
`configs/virtualbox/susnix-vm-resize.service`. The unit runs only inside VirtualBox
with the guest device available. Hyprland autostarts the user-session helper on
subsequent logins; it is guarded by `/dev/vboxguest`. No additional package is
needed beyond the existing `virtualbox-guest-utils`.

On the host, enable **View → Auto-resize Guest Display**, leave **Scaled Mode**
off, and use 100% VirtualBox scale. This changes the actual guest resolution
instead of stretching its pixels. The VM should use the VMSVGA graphics adapter.
Oracle documents the root bridge/session-helper arrangement in its
[Guest Additions guide](https://docs.oracle.com/en/virtualization/virtualbox/7.1/user/guestadditions.html).
The host UI and real guest resize handshake cannot be changed or tested from the
current tool environment, which has no VirtualBox guest device or compositor.

## Components and data

- `shell.qml`: one bar per screen and a manual reload IPC function.
- `Bar.qml`: panel surface and placement only. Top/left/right anchors provide full
  width; `exclusiveZone: 36` requests reserved space through layer shell. The
  namespace is `susnix-bar`.
- `components/`: logo, task, network, audio, CPU, GPU, clock, status row, and one
  shared text style (`StatusLabel.qml`).
- `theme/Theme.qml`: semantic color/effect bindings, category mapping, typography
  defaults, padding, and panel height.
- `theme/ThemeManager.qml`: JSON loading, validation, live switching, and global
  overrides. Six palettes live under `theme/themes/`.
- `components/Icon.qml`: palette-aware SVG icons without an icon font.
- `components/BarBackground.qml` and `theme/assets/cityscape.png`: a recolorable
  city backdrop inside the existing bar, rather than a desktop wallpaper change.
- `services/SystemStats.qml`: one shared collector across monitors. CPU comes
  from `/proc/stat` deltas every second while the bar is revealed, counting idle plus iowait as idle and
  excluding duplicate guest counters. The first sample displays a dash. Audio
  and NetworkManager state use native event-driven Quickshell services. Supported
  GPU utilization updates every two seconds; unavailable/virtual providers are
  retried every 30 seconds. NVIDIA queries fall
  back to AMD's readable `gpu_busy_percent` sysfs counters. Multiple supported
  GPUs show the busiest reading within the selected provider. Virtual drivers
  without a counter show `GPU VM`, failed providers show `GPU ERR`, and other
  unsupported GPUs show a dash. Audio without a sink shows `N/A`; networking shows
  WiFi, Wired, or Offline.
- `services/collect.sh`: guarded provider commands, two-second timeouts, fixed
  output locale, and safe creation of missing task state. No NVIDIA driver is
  installed by this change.
- `services/TaskService.qml`: watches and rereads task JSON, handles invalid
  data, recreates missing state without overwriting an existing task, and saves
  checkbox completion atomically while preserving additional JSON fields.
- `services/qmldir` and `theme/qmldir`: register the shared singletons.

The clock uses `SystemClock.Seconds` and local system time. The task is anchored
to the panel center, independent of side widths, with fractional center rounding
disabled. Long tasks elide. The task reserves 30% of the monitor width (up to
360px); the status row adapts its detail to the remaining right-hand space
while keeping text and icons at native scale. The task
stays visible on smaller VM displays instead of disappearing when status grows.
Date/network labels, resource icons, audio text, seconds, and dividers are
progressively omitted as available space tightens. At the smallest VM sizes the
GPU slot is omitted to keep the task, CPU, clock, and essential icons readable. The calendar icon occupies the
far-right slot after the clock; no calendar popup is implemented.

`StatusLabel.slotText` reserves a measured width for changing values. CPU/GPU
slots fit `100%`, audio fits percentage/mute states, and network/date/time slots
have fixed widths. Digit changes no longer resize the status row; the row is never scaled down.
The city PNG was created from the attached detailed skyline using the built-in
image tool. It has transparent alpha; the renderer crops the empty margins and
maps cyan/violet/magenta lighting into Primary/Secondary/Accent while retaining
brightness and transparency. It repaints only on load, resize, or palette changes
and works in the software backend. The exact edit prompt is recorded in
`theme/assets/cityscape.prompt.txt`.

Task state is automatically created at `~/.local/state/susnix/task.json`:

```json
{"task":"Implement top bar"}
```

Click the task field to edit it. Enter or clicking away saves the text; Escape
cancels an unsaved draft. The panel requests on-demand keyboard focus for editing.
The empty completion box shows a check only while pressed. Completing a nonempty
task archives the current field text and promotes the next queued task, or clears
the field when the queue is empty. The down arrow shows upcoming tasks and
today's completed tasks, newest first, with completion times and category colors.
Use the input and Enter or + to add upcoming tasks. Uncheck a completed task to
restore it to the queue; it becomes active immediately when the active field is
empty. Older entries remain stored but are omitted from today's list.

The same JSON file holds both task and archive atomically:

```json
{
    "task": "",
    "category": "dev",
    "taskPinned": false,
    "futureTasks": [{"id": "next-1", "task": "Test desktop", "category": "dev"}],
    "completedTasks": [
        {"task": "Implement top bar", "category": "dev", "completedAt": "2026-10-06T12:00:00.000Z"}
    ]
}
```

Existing task-only JSON remains supported, and additional fields are preserved.
Edits and rapid completion/save operations are serialized so they cannot lose
an archived task. Failed writes restore the last saved state and show an error.
Completion dates are stored as ISO timestamps; the dropdown filters in the
system's local timezone and refreshes the day at midnight (within 30 seconds).

The bar is visible at login until its first pointer hover. After that, the existing
350ms hide delay applies when the pointer leaves. This preserves autohide without
making a successfully autostarted bar appear missing.

The collapsed bar accepts pointer input at the 3px top edge and, when locked,
the pinned task section. Hover reveals the controls, and leaving waits 350ms before retraction, avoiding flicker when moving between
controls. Editing and open dropdowns keep it revealed.
The existing 36px reserved area stays stable while controls retract.

## Theme selector and panel finish

Click the faceted color cube at the top left to expand the six theme tiles
in a compact popup beneath the top-left color button. The SUSNIX text is removed.
Each tile previews its own palette and shows its full name. Click a tile to apply
and save it to the global colors JSON. The selected tile has a brighter border;
click the color cube again to collapse the strip. The window uses
`grabFocus: true` for an interactive popup role, rather than a tooltip. Clicking
outside dismisses it and synchronizes the color button so it can reopen. The strip scrolls horizontally
on narrow monitors and leaves the centered task and status row in place.

`SusnixLogo.qml` handles the color button, `ThemeStrip.qml` contains the palette
tiles, `ThemeCube.qml` draws palette-based
SVG facets and highlights, and `ThemeManager.qml` loads live palette previews.
`PanelDetails.qml` draws one continuous outer outline around the thinner
sides and taller task section, with static glass reflections and sparse circuit
traces. The separate full-width borders and inner task outline are removed. These effects support the software renderer, repaint only when
geometry, theme changes, or brief interaction effects; they introduce no dependencies
or continuous animation.
`TaskFrame.qml` draws borderless gradient glass, segmented terminals, and a
fine reflection inside the task section. The task title
is geometrically centered inside the frame. `TaskHistory.qml` renders the
queue/archive dropdown, `TaskQueueRow.qml` handles its rows, and
`TaskService.qml` owns editing, queue advancement, restoration, and lock persistence.
NYX's default skyline opacity is now 0.45; override `opacityBackdrop` in the
global JSON to adjust it. Every decorative color derives from the semantic palette.

CPU and GPU use matching `ResourceWidget.qml` containers with equal widths,
shared inner padding/spacing, and a fixed 6px gap. Their explicit labels remain
visible in compact mode; icons are removed first. Labels are separate from their
right-aligned numeric slots, so
changing digit counts cannot shift the label. `StatusLabel.qml` also reserves a
fixed font-metric height to keep baselines steady. Mouse-click tests exercised
all six themes, persistence, reselecting the active theme, and expand/collapse.
Geometry tests covered 1, 9, 10, 99, and 100 in normal and compact layouts.

Animation stays finite and uses cubic/quartic easing: `animationFast` defaults to
150ms, `animationDropdown` to 220ms, and `animationNormal` to 280ms. Dropdowns
unfold by 4px; task focus expands the centered pill by 6px and pulses its circular
indicator once. `EdgeSweep.qml` provides short bottom-edge hover sweeps.
`Icon.qml` lifts hovered icons by 1px and emits a small ring on audio changes or
actual network traffic. `SectionDivider.qml` briefly illuminates separators.
`AnimatedValue.qml` crossfades CPU/GPU numbers within fixed font-metric slots.

Hover discharges use `ElectricShock.qml`: short broken SVG strokes follow only
the hovered icon's vector outline, including theme cubes and task control icons.
Entering the bar or hovering a theme tile never triggers its full outline.

Brief cyberpunk glitches travel around the single outer outline on click interaction
and once per minute while the task is visible; icons and text are not sliced or
displaced. Theme changes propagate new accents from left to right along that
outline, without fading the desktop. `SkylinePulse.qml` occasionally lights three
small windows, a faint tower streak, and a low-opacity scan every 8–15 seconds.
The skyline image itself remains static. These effects support software rendering
and stop after their short bursts. Set `effects.glowStrength` to 0 to disable
decorative outline/skyline bursts. No notification system is introduced.

All panel reveals now share `Theme.animationReveal` and `Theme.revealEasing`:
the existing 150ms `animationFast` duration and `OutQuart` easing used when the
locked top bar retracts. The control center slides as one piece from the right,
with the same opacity/motion profile, and stays mapped until its close animation
finishes. Rapid toggles reverse from the current position instead of resetting.
Dropdowns use the same duration/easing. Opening no longer runs separate scans,
shards, module boot stages, or whole-bar ignition pulses; glass outlines remain
static. Resource graphs still interpolate real measurement updates.

## Control center

Press **Super + A** to toggle the panel on the focused monitor, or click the
sliders icon immediately beside the top-left theme cube. The shortcut targets
the active checkout/installed instance and starts the bar if it is stopped.
Manual toggle: `bash ~/.config/quickshell/susnix/bar.sh control`.
After installing the shortcut, run `hyprctl reload` once. The binding is defined
in `configs/hypr/hyprland.lua`; shell IPC routes it to the focused monitor without
launching a duplicate checkout/installed bar.
An independent layer panel hugs the right edge, from immediately below the 26px
right-hand bar strip to the bottom of the screen. Its width is the smaller of 340px or 45% of
the monitor width. Bar/desktop clicks keep it open; Escape, ×, the sliders button
and Super+A close it. It adapts to
the monitor height and fits all four main cards without scrolling. The graph
and placeholder adjust their heights; text/icons keep their native size. At very
small heights the AI placeholder becomes a compact header. The graph is capped
at 90px and retains percentage/time axes, network scale, and measured hover
values. The freed space goes to the assistant placeholder. App-group resource breakdowns remain visible. Opening it keeps the top bar revealed. Settings opens the theme selector.

The AI card is a static vector placeholder with no model/backend connection.
Scratch Note keeps plain text while the shell is running, including across popup
closes. It is intentionally session-only; reload/restart clears it.

System Performance collects detailed real samples every three seconds while open,
with lightweight aggregate snapshots every 15 seconds while closed. It keeps
1,800 samples in memory and offers views of the last 1/10/60 minutes. Choose 1m/10m/60m, toggle individual resource lines, and
hover the graph for timestamps and measured values. History starts with the
running shell, with no synthetic values or history before startup. CPU/GPU/RAM
and disk activity use a percentage axis; network uses a separately labeled peak
bytes/s scale. Unsupported readings leave gaps instead of appearing as zero.

The colored bars show Dev, Browser, AI, Media, and System. All group colors use
`Theme.categoryColor`; gray marks unattributed usage. CPU uses process tick
deltas divided by total CPU ticks. RAM uses RSS estimates apportioned within
used memory, with a gray remainder for cache/kernel/shared-memory differences;
RSS can double-count shared pages, so these are estimates. Disk colors show
per-process physical I/O byte shares of aggregate device traffic, while fill
shows the busiest disk's activity and the value shows total throughput. They are
I/O shares, not per-process disk busy time. PID start times protect against PID
reuse; missing permissions and disappearing processes are tolerated.

GPU totals retain the existing NVIDIA/AMD providers. NVIDIA `pmon` can supply
per-process SM activity for group shares; unsupported AMD/virtual counters or
missing per-process activity remain unattributed. Virtual GPUs still show
VM/no data. Network shows real aggregate traffic from `/proc/net/dev`; per-app
network accounting needs facilities not provided by this first version, so it
is explicitly total-only and gray. No privileged tracing or extra dependency
is introduced.

Rules/overrides are automatically initialized and saved in
`~/.config/susnix/resource-tasks.json` (respecting
`XDG_CONFIG_HOME`). Edit `tasks[].match` to tune substring matching; assignments
apply to all instances of that exact process name. Python defaults to Dev; assign
AI workloads explicitly if needed. Invalid group configuration keeps the last
valid settings. Process detection cannot infer what project/task a program is
working on, so these are app groups, not named task-queue items.

Quick Tasks launches installed desktop entries for Terminal, Files, Browser,
and Editor. ChatGPT opens its website in the default browser; it is separate
from the placeholder assistant. Missing applications are disabled. There is no installed-application search. Terminal-type
entries are wrapped with the existing Foot terminal. Settings opens Susnix's
palette selector. No launch is performed merely by opening the panel.

## Global theme configuration

`~/.config/susnix/colors.json` is created automatically on startup (or under
`$XDG_CONFIG_HOME/susnix` if that variable is set). Both installed and checkout
instances use this same global configuration. Edit it to recolor the shell live:

```json
{
    "theme": "Nyx",
    "colors": {
        "primary": "#00C8FF",
        "dev": "#00B8FF"
    },
    "effects": {
        "opacityPanel": 0.94,
        "opacityHover": 0.12,
        "cornerRadius": 3
    }
}
```

Only overridden values need to be present. `theme/colors.json` is the creation
template; editing an existing global file takes precedence. Colors use six-digit
`#RRGGBB` strings. Invalid JSON, unknown roles, or invalid values retain the last
valid configuration and emit a warning. Fix the file and it updates automatically.
Effect opacity and strength values range from 0 to 1; geometry and durations
are non-negative integers, up to 1000.

The 18 semantic roles are:

| Roles | Purpose |
| --- | --- |
| background, backgroundRaised | Base canvas and skyline |
| surface, surfaceRaised | Glass surfaces and elevated surfaces |
| primary, secondary, accent | Cyan/violet/magenta defaults; interactive accents |
| text, textMuted, border | Readable text and subtle separators |
| success, warning, danger | Completion and status feedback |
| dev, browser, ai, media, system | Consistent resource/task categories |

The audit found eight literal colors, all in the original `Theme.qml`: background,
surface, primary, secondary, accent, text, textMuted, and border. They now come
from palettes. Opacity literals for panel/hover/borders and component radii and
border widths were replaced with shared effects. No theme color literals remain
in QML components. The PNG source contains its original artwork colors; the
Canvas remaps those into the current semantic palette at render time.

Shared effects are `opacityGlass`, `opacityPanel`, `opacityBackdrop`, `opacityInactive`,
`opacityDisabled`, `opacityBorder`, `opacityGlow`, `opacityHover`, `blurRadius`,
`glowStrength`, `borderWidth`, `cornerRadius`, `animationFast`,
`animationDropdown`, and `animationNormal`. Hover and glow colors derive from semantic colors and alpha.
Blur radius is available for future surfaces;
this change does not add compositor blur rules or a full-panel glow effect.

Task JSON can include `"category": "dev"`, `"browser"`, `"ai"`, `"media"`, or
`"system"`. `Theme.categoryColor(category)` is the common mapping for task
indicators and future graphs/usage bars/legends. The task defaults to Dev,
CPU/GPU icons use System, and audio uses Media. Network availability uses the
primary/muted status roles. Completion uses Success. Graphs and usage breakdowns
are not present in v1 and are not introduced by this theme refactor.

Switch the running checkout instance manually:

```bash
quickshell ipc -p /home/levi/susnix/configs/quickshell call bar theme Sakura
quickshell ipc -p /home/levi/susnix/configs/quickshell call bar theme Ember
quickshell ipc -p /home/levi/susnix/configs/quickshell call bar theme Nyx
quickshell ipc -p /home/levi/susnix/configs/quickshell call bar currentTheme
```

For the installed instance, replace `-p /home/levi/susnix/configs/quickshell` with
`-c susnix`. Names are case-insensitive through IPC. Switching persists the
selection and clears color overrides so the chosen palette is shown faithfully;
effect overrides are preserved. Direct JSON editing allows choosing a palette
with your own overrides.

To add a theme, copy a palette JSON to `theme/themes/MyTheme.json`, change its
18 colors, and add `"MyTheme"` to `ThemeManager.availableThemes`. Effects are
optional and inherit NYX defaults. Reload once after adding the file and switch
using `call bar theme MyTheme`. No component edits are needed.

## Desktop controls and reduced idle work

Device Controls sits above the AI placeholder. Everything fits at the live VM
size and at a 700px panel height; shorter layouts use compact device/music cards.
Wi-Fi and Bluetooth tiles open bounded device sheets, without scrolling the
whole control center. Sheets have a Back button and Escape returns to the main
panel; a second Escape closes it.

- Wi-Fi: adapter toggle, signal/security and connected state, saved connections,
  open/WPA/WPA2/WPA3 personal network connection with masked password entry,
  disconnect, and failure messages. Scanning runs only while the network sheet
  is open. Enterprise networks require a preconfigured NetworkManager profile.
- Audio: native output volume and mute, output device selection, microphone
  selection and mute. The bar shares these live values without `wpctl` polling.
- Bluetooth: power, discovery, paired device connect/disconnect, and a Pair
  devices button that opens Blueman for PIN/confirmation handling. No custom
  pairing agent or automatic trust of unknown devices is added.
- Brightness: backlight slider with hardware/permission detection; updates are
  committed on release rather than spawning a command per pointer movement.
- Session: themed Hyprlock plus logout/restart/shutdown. The latter three show
  an in-panel confirmation. Failures remain visible in the UI.

Packages added to `packages/desktop.txt`: `bluez`, `blueman`, `brightnessctl`, and
`hyprlock`. Bootstrap enables Bluetooth alongside NetworkManager. On an existing
installation, install these with:

```bash
sudo pacman -S --needed bluez blueman brightnessctl hyprlock
sudo systemctl enable --now bluetooth
```

The live VM has working audio and wired networking, no Wi-Fi/Bluetooth adapter,
no backlight, and no installed Hyprlock/Blueman. Sudo requires a password, so
those package/service changes were prepared but could not be applied unattended.
Lock configuration is generated temporarily from the selected Theme palette;
existing Hyprland and lock configuration files are not overwritten.

Idle optimization: native network/audio events replace repeating command
processes. Detailed per-PID collection stops while closed; aggregate history
continues every 15 seconds. A single awk reader handles process statistics when
open. CPU reads and numeric crossfades stop while the bar is hidden. The clock
uses minute precision while hidden and seconds when revealed. Graphs repaint
only while open, interpolate briefly at 30fps, and limit vertex count to their
pixel width. Theme reflections, skyline and existing finite interaction effects
remain in place. History contains measured snapshots with timestamps, so the
longer background interval does not create artificial points.

Validation: all QML linted, shell syntax checked, live volume round-trip restored
the original 40%, fake Wi-Fi verified password/saved/disconnect dispatch, isolated
MPRIS tested playback and seeking, and device sheets/layouts exercised offscreen.
`python tests/test-desktop-controls.py` verifies brightness validation, fixed
session dispatch, Bluetooth paths/methods, and themed temporary lock config.
Reboot, shutdown, logout, and actual screen locking were not invoked on the
running desktop. Wi-Fi/Bluetooth/backlight hardware operation cannot be checked
in this VM.
